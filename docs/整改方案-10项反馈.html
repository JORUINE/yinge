A真 Bug（5 条 · 我已定位根因）

A1 投票限流太紧 必修

现象隔 1~2 秒点就弹"操作过于频繁" 根因后端把两次投票的最小间隔写死成 3 秒
backend/src/config/index.js → vote.minIntervalMs 默认 3000（毫秒）
vote.service.js → checkLightRate()：now - 上次投票 < 3000 → 抛错
我的处理：最小间隔降到 250 毫秒（只拦手抖连点），每分钟上限 20 → 120，每天 300 → 800；前端同时加"请求中禁用"，避免重复提交。真正防刷靠后面的"异常投票判定"，不靠卡间隔。

A2 现场/演唱会专辑漏筛 必修

现象陶喆「Soul Power (現場原音專輯)」进了对决池 根因剔除规则里"现场"只写了简体字，而繁体资料库返回的是「現場」
backend/src/modules/music/admission.js
live: ['live','现场','演唱會','演唱会',...] ← 缺繁体「現場」
专辑名 = "Soul Power (現場原音專輯)" → 没命中 → 被判合格
我的处理：关键词补全繁体（現場 / 演唱會 / 電影原聲 / 精選…），并在匹配前做繁简归一，杜绝同类漏网。结论：现场专辑本就该排除，这条修完 Soul Power 会自动消失。

A3 多歌手场次过长（3 歌手 30+ 场） 必修

现象3 个歌手要比 30 多场，进度条 11/30，太长 根因多歌手模式没让用户限定每人张数，后端把每位歌手的全部合格专辑都拉了进来
BattleCreateView.vue → payload.artists = [{artistId}]（不传 albumCount）
battle.service.js resolvePool('multi-artist') → take = 全部合格专辑
bracket.js 组容量 = min(3, 歌手数) → 3 歌手时每人 N 张 → 场次 = 3N + 2
我的处理：多歌手模式加"每位歌手取前 N 张"选择（默认 4 张，可选 3~6）。3 歌手 × 4 张 → 14 场（原来 30+）。场次公式会写进文档并让前端实时显示"预计 N 场"。

A4 轮空被显示成"战胜 — 0 : 0" 必修

现象夺冠之路里出现"半决赛 战胜 — 0 : 0" 根因某轮参赛数为奇数时有一张轮空，被当成一场"对手为空"的比赛渲染
battle.service.js getResult()：轮空场 rightAlbumId=null、winner=null → 前端取到 opponent=null
BattleResultView.vue:29 → 战胜 {{ opponent?.name || '—' }}，比分固定 0:0
我的处理：轮空场单独标记为「轮空，直接晋级」，不显示成对阵；夺冠之路按轮次成组展示。

A5 按年代模式不可用 必修

现象选"按年代"点开始 → 红字"这些专辑无法组成跨歌手对局" 根因两处叠加：①选择页根本没有年代区间输入框；②后端该模式返回的歌手列表为空，导致分组每组只有 1 张 → 0 场 → 报错
BattleCreateView.vue → era 模式无 year 输入（用默认 2000-2020）
battle.service.js resolvePool('era') → return { albums:list, artists: [] } ← 空
createBattle → groupAlbumsCrossArtist(albums, 0) → 组容量=1 → 0 场 → 抛"无法组成跨歌手对局"
我的处理：①加年代区间选择器；②后端从该区间专辑里提取真实歌手、按每歌手取前 N 张控制体量；③统一场次公式。修完"按年代"才真正可用。（"手动挑选"目前也是未开放的占位，一并做掉。）

B体验问题（4 条 · 我直接改）

B1 轮次切换没有过渡 体验

现象小组赛打完直接跳半决赛，不看左上角文字根本不知道换轮了 根因投票页只刷新了对阵数据，没有任何"轮次变化"的提示
我的处理：加"小组赛结束 → 进入半决赛"过渡浮层（含本轮晋级名单一闪），轮次徽标加大 + 入场动效。

B2 夺冠之路太单薄 体验

我的处理：重做成完整晋级路线：每轮「对手封面 + 比分 + 胜/轮空」逐轮串联，顶部冠军卡加大，并在下方补一段"冠军共经历 N 场、得票 M"的说明，让"为什么是冠军"一目了然。

B3 指定对决结束太快 体验

我的处理：功能保留；结果页增强 —— 加胜负占比、双方胜场对比条、可"再来一组"按钮；创建页在只排 1 组时提示"组数偏少，结果参考性有限"。

B4 选择歌手显示编号 体验

根因界面上直接把 iTunes 的 artistId（如 #300117743）列出来了
我的处理：去掉编号，改成「头像（取该歌手首张专辑封面）+ 姓名 + 流派」；同名歌手靠头像与流派区分。

C设计决策（2 条 · 我按规则定稿）

C1 对位赛平局无意义 + 10 张上限 设计

现象陶喆 5 : 5 周杰倫，看着没意义；上限 10 张，周杰伦专辑多反而吃亏
我的定稿：①胜负规则改为「先比胜场，胜场相同比总票数」，都不分才算平局（对位赛每场只有 1 票，平局本就高频，用总票数兜底才合理）；②张数上限从 10 放宽到「各歌手可用专辑的最小值」，默认 5 张，前端实时显示预计场次，避免又长又懵。

C2 还原 UI demo 首页 设计

现状原型（19 页）里那套"你的最爱专辑，由你亲手决出"首页，目前线上还是简化版
我的处理：列为独立一批（视觉大改），从首页 + 对决投票页两个最高频页面开始还原，逐步铺到其余页面。范围与节奏见下方批次。
