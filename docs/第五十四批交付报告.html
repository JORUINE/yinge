1你提的三条，逐条结果

你的反馈结果根因 / 修法 / 实测数字
① 手机端方形图和竖形图只在"高"上有区别，宽的一样，非常不对已达成 根因：方形卡的高度是写死的 min-height:430px，而宽度跟着布局走 （手机 342 / 桌面 420）⇒ 手机 342×430=0.795、桌面 420×442=0.950。 你看到的"两端不一样"，本质就是宽度没锁死、高度锁死了。
修法：改成 aspect-ratio:1/1（高度由宽度推出 ⇒ 任何宽度都正方）， 内容用 --sqk 整体缩一档才装得下，字号一律带 12px 硬下限。
实测：手机 342×342=1.000、桌面 420×420=1.000，导出 PNG 都是 1080×1080； 7 个文字元素全部在卡内、0 个溢出。
② 导出的图和页面上看到的不一致（色调 + 左上角「音格」可读性），人格卡也要一样已达成 根因（实测确认）：导出是"克隆 DOM + 内联样式"，而这张卡的整套配色都在伪元素里 —— .scard.glassy::before = 顶部压暗 + 冠军色三层柔光 + 深色纱幕 + 底部托底（色调）， ::after = 左上主高光 + 斜穿光带 + 底部微光（玻璃质感）。 cloneNode 不克隆伪元素、克隆节点又脱离样式表 ⇒ 这两层在导出里整层消失。 于是「音格 · YINGE.APP」直接压在没压暗的亮封面上 ⇒ 可读性差、色调发飘。
修法：导出前把 ::before / ::after 实体化成真元素再内联样式 （cardExport.js 的 materializePseudo）。 人格卡同理（它的白纱幕也在 ::after）—— 一处修复，4 个导出入口全部受益。
实测：预览截图 vs 真导出逐区域比像素 —— 整卡亮度差 手机 1.9 / 桌面 1.2， 品牌行差 手机 0.0 / 桌面 0.3；人格卡整卡差 0.6 / 0.8。
