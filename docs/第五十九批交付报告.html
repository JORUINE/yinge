2导出：把"跨域"这个根因掐掉（同源代理）

为什么之前三轮都没修好：我一直在"哪条取图路径更稳"上打补丁，但所有路径的失败根源都是同一个词——跨域：

路径在 iOS 上为什么会失败
canvas 重绘跨域 <img> 没带 crossorigin 就污染画布，toDataURL 直接抛错
fetch 取 blob依赖对方回 CORS 头，且真机上 fetch 本身可能被系统策略拦
带 crossorigin 重载同样依赖 CORS 头；Safari 对跨域位图的二次解码还可能直接失败

这次的做法（结构性）：后端加一个只放行图片白名单域名的同源代理

GET /api/img?u=<原图地址> · 白名单：mzstatic.com（Apple 封面）、music.126.net 等 · 只允许 http/https，只返回 image/*，8MB 上限，8s 超时 · 返回 `Cache-Control: public, max-age=604800, immutable`

前端导出时把封面地址换成这个代理地址 —— 同源 ⇒ 画布永不污染 ⇒ toDataURL 永远可用 ⇒ SVG 里一定有图。 与设备、引擎、网络策略都无关。这条现在排在取图链路的第一位，后面三条老路只作兜底。

实测：代理 200 / image/jpeg / 84 KB；非白名单 403；缺参数 400。 分享卡竖版导出时 /api/img 命中 4 次；再拦断所有跨域 fetch 重新导一张人格卡，仍然完整（色 212 / 透明像素 0.1%）。

3关于人格卡：一条重要的事实

我必须说清楚：人格卡的背景是 /img/personality/bg-XXX.jpg —— 同源本地图，本来就不涉及跨域。 所以这次的代理帮不到人格卡（探针里它命中代理 0 次，这是对的）。 也就是说"人格卡导出没图"若在 iOS 上仍然发生，根因不是 CORS，而是SVG foreignObject 在那个引擎里没把那张图渲染出来，或最终 PNG 被写坏。

我这边的事实（可复现）：六种人格卡逐个导出、直连与「我的测评 → 回看」两条入口都试过， 全部 1080×1440、不透明、中心亮度与页面背景一致，看不出任何差异。所以这个问题我只能靠你那张文件定位。

你只要给我一样东西，我就能定位：iOS 上导出失败的那张保存出来的 PNG 原文件（不是截图）。 拿到它我可以判断：整张空白（渲染失败）／有文字无图（图没进 SVG）／有图但错位（布局问题）—— 三种对应三种完全不同的修法。

如果它确实是"有文字无图"，我下一步就把人格卡与分享卡一起改成 html2canvas 优先 + 伪元素/阴影补偿（你先前提过的"特效有问题"那一类），而不是继续修 SVG 路径。 这一步我会先出对比图给你选，不擅自改。
