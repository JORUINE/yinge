## 四、踩过的坑（重要，避免重复）

### 坑 1：HTML 转 DOCX 时，表格列宽不受 CSS 控制

- **现象**：给 `<td>` 设 `width:20%` 或 `width:8em` 都无效，转换器自行分配列宽，
  导致"学　院：""指导教师："这类短标签列被压得极窄而**折成两行**。
- **结论**：**做"表单式抬头"不要用多列表格**。
- **正确做法**：改用普通段落，一行为一整段，只受页面宽度限制；
  需要"填空横线"时用 `<u>...</u>` 包住值，并用全角空格把值补齐到等宽。
- **核算方法**：A4 + 左右边距 3.17cm 时**正文可用宽度仅 416pt**；
  先把"每行全角字符数 × 字号 + 半角字符数 × 字号 ÷ 2 + 左缩进"算出来，**留 30% 以上余量**。

### 坑 2：关系标签被线条/框遮挡

- **现象**：ER 图的关系标签画在折线中点上，会被后画的线或表格框盖住。
- **正确做法**：标签位置**放在源表格出线口旁边**（落在列间空隙里），
  并且**所有标签最后统一绘制**；同一个表引出多条线时，出线点要沿框边错开。

### 坑 3：ER 图连线穿过表格框

- **原因**：折线中点取两框中心之间，必然穿过中间的表格。
- **正确做法**：跨列的关系线**绕到画布左右两侧的走线通道**再折回，
  每条线占独立的横向偏移（本项目用 18px 间隔）；通道留在 `MARGIN_X` 之外，保证不压框。

### 坑 4：Word 每次打开都弹「是否更新该文档中的这些域？」

- **现象**：打开 docx 时弹出「该文档包含的域可能引用了其他文件。是否更新该文档中的这些域？」
- **原因**：`html_to_docx` 引擎会在 `word/settings.xml` 中写入 `<w:updateFields w:val="true"/>`。
- **修复**：本文档没有需要更新的域（无目录、无页码、无交叉引用），直接**删除该节点**即可。
  已封装为脚本 `tools/fix_docx.py`，转换后跑一次：

  ```bash
  "C:\Users\胡祖锐\.venv-html-to-docx\Scripts\python.exe" tools/fix_docx.py <文件.docx>
  ```

### 坑 5：段落太长导致"看起来像表格折行"

- **现象**：抬头明明写的是普通段落，Word 里却把"学　院：""指导教师："折成两行，
  看起来像是表格列宽不够。
- **真相**：**不是表格问题，是整行太长放不下。**
  A4 + 左右页边距 3.17cm 时，正文可用宽度只有 **416pt**；
  而一行塞两组"标签+值"约需 **372pt**，余量仅 10%，字体稍有差异就折行。
- **修复**：**一行只放一组"标签+值"**（本项目 6 行），每行仅约 **180pt**，余量为可用宽度的一半以上。
- **核算公式**（务必先算再写）：
  - 可用宽度 = (11906 − 左页边距 − 右页边距) ÷ 20 pt
  - 行宽 ≈ 全角字符数 × 字号 + 半角字符数 × 字号 ÷ 2 + 段落左缩进
  - **留 30% 以上余量**，不要贴着上限写

### 坑 6：生成 docx 时文件被 Word 占用

- **现象**：`Permission denied`。
- **判断**：目录里出现 `~$xxx.docx` 锁文件即说明 Word 正开着。
- **处理**：先关 Word；或先输出到别的文件名，稍后再覆盖。

### 坑 7：中文字体必须同时写 ascii / hAnsi / eastAsia

- **现象**：`run.font.name = "宋体"` 之后，Word 里正文仍显示为等线或 Calibri。
- **原因**：python-docx 的 `font.name` 只改 `w:ascii`，**中文走的是 `w:eastAsia`**，
  不写这一项，Word 会用默认西文字体回退渲染中文。
- **正确做法**：拿 `run._element.get_or_add_rPr()` 找到 `w:rFonts`，
  把 `w:ascii` / `w:hAnsi` / `w:eastAsia` **三个属性都设成同一个中文字体名**。

### 坑 8：行距数值不是"倍数"

- OOXML 中 `w:line` 的单位是 **1/240 行**：`240` = 单倍，`360` = 1.5 倍，`480` = 双倍。
- python-docx 里写 `paragraph_format.line_spacing = 1.5` 即自动换算为 360，
  但**直接检查 XML 时不要按倍数读**，否则会误判。

## 五、已知限制

- `html_to_docx` 引擎对复杂表格（colspan/rowspan）支持有限；
- 该引擎对表格单元格的内边距、对齐等 CSS 控制较弱 —— 表格类内容尽量从简；
- 中文渲染依赖系统字体（脚本用 `C:\Windows\Fonts\msyh.ttc` 微软雅黑）；
- PPT 与 ER 图脚本目前用的是固定排版，若内容量大改，需同步调整版式参数。
