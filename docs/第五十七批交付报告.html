1对位赛分享图：右上角「对位赛 · 战报」被劈成两行

你截图里保存下来的图是「对位赛 · 战」/「报」，页面上却是好的。这不是写错字，是**导出时字体度量差了一点**：

导出走「克隆 → 内联 computed style → 塞进 SVG 画出来」，克隆体在另一个文档里渲染， 字体度量与页面可能差零点几像素。那个胶囊是弹性布局的子项、默认"自动尺寸"， 页面里刚好放下、克隆体里差一点就在文字内部换行。第五十五批在分享卡的方形图上栽过同一手（专辑名叠在一起）。

修法（固定两条）：子项 flex:0 0 auto + white-space:nowrap， 容器 flex-wrap:wrap —— 真放不下时在元素之间换行，而不是把一行字劈开。 宽度够的时候观感完全不变。

断言：在导出 PNG 的右上角区域数"文字行" 改前：2 行（"75-118" + "244-249"） 改后：1 行（44px 高）✅

3iOS 真机保存依旧丢图 —— 这次挖到 5 个具体机制

你的原话：「电脑端按 F12 模拟手机确实能直接保存、图片也没问题，但手机端真机 iOS 上点保存还是进这个页面（文件预览），保存的图还是依旧丢失图像」
这条线索极其关键：F12 模拟手机走的还是**桌面 Chrome 的渲染引擎**， 所以它一直"正常"；真机上是 WebKit，两者在这里的行为完全不一样。我按"真机上会怎么失败"逐条挖，挖到 5 个：
#机制后果状态
1晋级图组件里的封面还没带 crossorigin（BracketListView 2 处、BracketNode 3 处） 图能显示，但画进 canvas 会污染画布 ⇒ toDataURL() 抛 SecurityError ⇒ 这张图必丢 已补
2缩略图按 600×600 原图内联（页面上一张才 26px） 15 张封面把 SVG 撑到 1.9 MB，真机解不动这么大的图 按渲染尺寸 ×3 降采样（48~512px）
3每个元素都把继承来的 CSS 变量整份抄一遍
（99 个元素写出 1.87 MB 样式，平均每个 19 KB）		 同上：SVG 越大越容易在真机上解码失败 只保留"被真正改过"的变量（值等于父元素就跳过）⇒ 样式 1.87→0.99 MB
4fetch(超长 dataURL) 在 iOS 上会截断
（保存那一步原来是 await (await fetch(dataUrl)).blob()）		 写进"文件"的是一张 残缺的 PNG —— 大小看着有（你那张 2.1 MB）、系统连缩略图都出不来， 这正好对上你截图里那个灰白的 PNG 图标 改成 atob 自己解 base64 再拼 Blob，不经网络栈、无长度上限
5兜底的 html2canvas 被按视口裁剪 主路径一失败就掉到它，而它把晋级图截成 780×780 的方图（你要的那张是 1400 高） 显式传入元素的 scroll 尺寸 + 撑开 clone 窗口
排障中我自己踩的两个坑，也记下来：
① 我一度判断"是 data URL 太长解不了"，于是换成 URL.createObjectURL(blob)—— SVG 能解码了，但画布被污染（blob 的 SVG 画进 canvas 后 toDataURL 直接抛 "Tainted canvases may not be exported"），只能回退。**长度从来不是病根。**
② 我在改这个文件的过程中**把模板串末尾的 </svg> 弄丢了**（编辑器匹配范围比预期大）， 于是 SVG 解析报 Unexpected end of stream。我是靠"打印 SVG 结尾 220 个字符"当场看出来的。 教训：改完这类拼接字符串，必须把产物结尾打出来看一眼。

还加了一道"结果自证"：导出画完之后，拿页面里每个 <img> 的位置去导出画布的同一块区域数颜色——纯色说明这张图没进去。超过一半的图是纯色， 就判定"图丢了"，自动换引擎重来。这比"看文件大小"可靠得多： "图丢字留"的时候体积照样很大，旧判据永远放行。

手机档完整晋级图导出（拦断全部跨域 fetch 的真机级环境） 改前：780 × 780（被裁成方图，封面灰块） 改后：1400 × 1398，四边干净（左1/右1/上1/下1 种颜色 = 纯背景），622 种颜色
必须跟你说清楚：我没有 iPhone，最后这一步只能你验。 上面 5 条都是"真机上会失败的具体机制"，并且每条都有对应的改动和断言； 但"iOS 上是不是真的好了"我给不出实测数字。如果还丢，请把保存出来的那张图发我，我按它的像素继续查。

4手机端完整晋级图：横竖都错

你截图里：竖版右边被切掉一块、封面变灰块、冠军卡压着一块白；横版冠军卡被裁在画面外。三个原因：

原因为什么会这样修法
导出时带着"观看用的缩放" 手机子页为了适配宽度给外层加了 CSS zoom；而导出是克隆内层元素，祖先的 zoom 不在克隆树里 ⇒ "看得见的比例尺"和"导出来的比例尺"不一致 ⇒ 右边被切 导出前把 zoom 归 1、导出后还原（before-export 钩子）
导出态被强制 width:100% 这是我上一批为了"手机一屏看得全"加的规则，结果连导出那一瞬间也生效了 ⇒ 内容被挤进 382px 规则收窄成 :not(.exporting)，导出仍走 max-content（与桌面同一条路）
标题与冠军名被劈行 同第 1 条：fit-content 宽度被钉死，克隆体里字体度量一变就折行；而卡片高度也被钉死 ⇒ 折出来的第二行被裁 「音格 · YINGE.APP」与标签 nowrap；冠军名 / 歌手行改 width:100%（第五十五批同一口径）
实测：竖版导出 1400×1398、横版 480 KB，封面全在、冠军卡完整、 四边都是干净背景（左1/右1/上1/下1 种颜色）。两张成品图我都打开看过了。
