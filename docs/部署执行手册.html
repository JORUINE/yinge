部署执行手册 · 2026-10-14 · 你选了「先部署上云」

音格 · 照着做就能上线

这份手册把每一步点什么、填什么、怎么算成功都写死了。你只需要做三件事：注册三个平台的账号、把下面的值粘进去、点几下鼠标。所有命令我已经在你机器上真跑过（数字见每步的「实测」）。

① MongoDB Atlas存数据的云数据库免费 512MB，够用
② Render跑后端 API（Node）免费档会休眠，见 §6
③ Vercel托管前端网页（静态）免费，全球 CDN
④ GitHub三个平台都从这儿拉代码你已经 push 过了
先看清全貌：上线后数据怎么流
别人手机/电脑 → 打开 Vercel 网址（网页）→ 网页里的按钮调用 Render 网址的 /api（后端）→ 后端读 Atlas（数据库）。
对应到你现在本机：localhost:5173（网页）→ localhost:3000（后端）→ localhost:27017（库）。
所以顺序不能乱：必须先有 Atlas（库）→ 再有 Render（后端）→ 最后 Vercel（前端），因为后一步要用前一步的地址。

1第一步 · MongoDB Atlas（先把云库建好）

  1. 注册并登录
    打开 mongodb.com/atlas，用邮箱或 Google 账号注册（免费，不用信用卡）。
  2. 建一个免费集群
    登录后它通常直接弹「Create a cluster」。选 M0 Free（512MB，我们数据只有 17.87MB，绰绰有余）， 提供商和地区随便选一个离你近的（如 Singapore / Tokyo），名字默认 Cluster0 即可，点 Create。
    ⏱ 这一步要等 1~3 分钟，它在 Provision。
  3. 建一个数据库用户（重要，不是登录账号）
    左侧 Database Access → Add New Database User → Username 填 yinge、Password 点 Autogenerate Secure Password， 立刻复制保存（只显示这一次，忘了只能重置）。 Privilege 选 Read and write to any database。
  4. 放开网络访问（关键，不然后端连不上）
    左侧 Network Access → Add IP Address → 选 Allow Access from Anywhere（就是 0.0.0.0/0）。
    ⚠️ 为什么必须放开：Render 每次请求的出网 IP 都不固定，写死某一个 IP 明天就连不上了。这是免费档的常规做法。
  5. 拿连接串
    回到集群页点 Connect → Drivers → 复制那串 mongodb+srv://…。 它长这样（把尖括号换成你的）：
# Atlas 连接串模板（密码里的特殊字符要先 URL 编码，见下）
mongodb+srv://yinge:你的密码@cluster0.xxxxx.mongodb.net/yinge?retryWrites=true&writesConcern=majority
⚠️ 密码编码这条最容易栽：如果 Autogenerate 出来的密码里带 @ # / ? % : 这些字符， 直接粘进连接串会把串截断，表现为「连 Atlas 超时 / bad auth」。替换表：@→%40、#→%23、 /→%2F、:→%3A、%→%25、?→%3F。 嫌麻烦就在 Database Access 里把密码改成只用字母和数字。
本步验收：不用敲命令也能验 —— 集群页左边出现 Collections 菜单、Connect 按钮能点出连接串，就算建好了。

2第二步 · 把数据搬到 Atlas（不搬就是空站）

为什么必须有这一步：Atlas 是台新数据库，里面一条数据都没有。 你现在本机库里有 45064 条（33428 张专辑、485 位歌手、350 局对战、3746 票、50 道题、6 型人格…）。 不搬的话，线上能打开、能注册，但一开局就没专辑、测评没题目、榜单是空的。

搬数据用仓库里现成的脚本（我已经写好并真跑过）。先只读演练看一遍会搬什么，再真搬：

# 1) 只读演练：只报"会搬什么"，一个字节都不写。先跑这个。
cd E:\桌面\毕业设计\yinge\backend
node scripts/migrate-to-atlas.mjs

# 2) 确认无误后真搬（把引号里换成你在上一步复制的 Atlas 连接串）
node scripts/migrate-to-atlas.mjs "mongodb+srv://yinge:你的密码@cluster0.xxxxx.mongodb.net/yinge?retryWrites=true&writesConcern=majority" --apply
本步实测（我在你机器上真跑到临时库的结果）：14 个集合全部成功、条条一致 —— albums 33428 / tracks 3570 / votes 3746 / battlematches 2047 / battlegroups 1165 / battles 350 / artists 485 / users 73 / personalityquestions 50 / personalityresults 36 / albumtagvotes 66 / favorites 26 / combos 16 / personalitytypes 6，合计 45064 条。
脚本还会做外键抽检（证明 _id 原样搬过来、关联没烂），实测 5 条全中：对局 _id、albumIds[0]、userId、 championAlbumId、淘汰赛胜方专辑，在目标库全能找到。✅
安全设计（防止误操作）：① 默认只读演练，不加 --apply 什么都不写； ② 目标集合非空时默认拒绝覆盖（防止冲掉线上已有数据，要覆盖得显式加 --force）； ③ 全程保留 _id —— 库里 albumId / userId / winnerAlbumId 全是 ObjectId 外键，重新生成 id 会让关联瞬间全烂。
索引不用搬。后端的 Model 里都写了索引定义，连上 Atlas 时会自动建（实测启动日志 MongoDB 已连接 即就绪）。

这条是构建时变量：加完之后必须点一次 Redeploy 才生效，光保存不重新构建，页面还会继续打旧地址（表现为"接口全 404 / Network Error"）。
还有一件事必须回 Render 做：Vercel 部署完会给你一个域名（如 https://yinge.vercel.app）。 拿着它回 Render → 你的服务 → Environment → 把 CORS_ORIGINS 填成这个域名 → 保存（Render 会自动重启）。
两边都配，浏览器才不会拦跨域请求。只配一边的典型症状：网页能打开，但一调接口就红字 CORS policy / Network Error。
仓库里已经放好了 frontend/vercel.json，它干两件事：① 把所有未知路径都指回 index.html —— 否则你在 /battle/xxx/bracket 这种地址刷新会 404；② 给 /assets/ 下的文件加一年长效缓存。 你不用改它。
本步实测：我重新构建过 dist 并验通引用链（index.html → 入口 js → 动态 import 的 BracketTree chunk → 里面确实含本轮新代码），vercel.json 也验证是合法 JSON。 仓库 283 个文件 / 24MB、没有任何 >2MB 的文件、node_modules 没入库 —— 克隆和构建都不会被拖垮。

6两件必须知道的事（免费档的脾气）

① Render 免费档会「睡觉」。超过 15 分钟没人访问，它会自动停机；下一次访问要 30~60 秒才能唤醒。
答辩当天这么做：轮到你之前，自己先用手机流量打开一次网址、点两下，把它唤醒；然后 15 分钟内讲完就行。
想彻底解决（一次性设置，之后不用管）：注册一个免费定时访问服务（如 cron-job.org）， 新建一个任务，URL 填 https://你的服务名.onrender.com/health，间隔设 每 10 分钟。 它每隔 10 分钟敲一次门，Render 就永远不睡。
② Atlas 免费档 512MB。我们现在数据 17.87MB、索引 3.92MB，离上限极远，不用管。
