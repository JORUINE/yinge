1你最关心的：保存下来图片丢失

你的原话：「移动端保存图片后是进入了预览，然后我点下面的分享 保存图像 出现那个问题 会是因为走这里的原因吗」
不是。iOS 那个分享面板只是把已经生成好的 PNG 文件递出去 —— 图在点"下载"那一刻起就已经是空白的了， 走不走分享面板、点不点"保存图像"，结果完全一样。问题在取图那一步。

根因（实验坐实，不是推测）

导出前要把 `` 的封面转成 base64 塞进 SVG。原来的做法是 fetch(src, {mode:'cors'}) —— 而它在真机上会失败： iOS Safari / 微信内置浏览器对跨域 fetch 管得更严，iTunes 图片域名不一定放行。 一旦 fetch 失败，代码就"保持原 http 地址"，而 SVG 当图片用时浏览器根本不加载外部 URL ⇒ 封面和缩略图全变成空白框，只剩文字。

实验（_r55-imgdiag.mjs）：只 abort 掉 resourceType==='fetch' 的图片请求、 让页面上的 `` 照常加载 ——

关键发现：同一次实验里 canvas 重绘 100% 成功，即使 fetch 被完全拦断。
原因：那些 `` 都带 crossorigin="anonymous" 且已经在页面上加载成功了 （否则你根本看不到封面）⇒ 浏览器手里的就是带 CORS 头的位图 ⇒ drawImage 进画布不会污染 ⇒ toDataURL() 一定可用。它不需要再发一次网络请求，真机可靠性远高于 fetch。

修法：saveImage.js 与 cardExport.js 的取图主路径都改成 canvas 重绘优先、fetch 兜底。

为什么这一改就覆盖了你说的三处：分享图 / 对位赛详细战报 / 人格卡， 4 个导出入口全部走同一个 utils/saveImage.js ⇒ 改的是公共取图函数，一处修复全部受益。 这正是"改一处改全部引用"——反过来说，也是上次漏 CS 的意思：我当时只以为问题出在 SVG 引擎。

2PC 端你圈的四处

你的反馈结果根因 / 修法 / 实测
① 电脑端怎么多出个这个文本已修 根因：第 51 批做的「弹层内操作条」.mobar-in-sheet 只写了 v-if="sheetOpen"， 漏了 isPhone（注释里写着"桌面档不渲染"，但代码没实现）。 手机端选完模式会 sheetOpen=true，PC 端也一样 ⇒ 而 PC 端 .opts 是 display:contents，这块就直接裸躺在筛选区后面，成了"多出来的一段文本"。

② PC 端播放器做得和上面一样长，中间布局跟着适配已修 根因：桌面档 .nowbar 是 max-width:560px; margin:auto —— 当初加它是怕"拉宽后歌名居中在 900px 里显得空"。但结果是上面的对决区撑满内容区、播放条只有 560px， 两者长度差一大截。

⚠️ 只有"手机端"没动：≤640 仍是原来的「上信息 + 中转盘」竖排，一根线都没改。
③ PC 端导出的方形图里专辑名叠在一起了
（但分享页上是正常的）		已修 根因（实测，很反直觉）：.smain 是 flex-column + align-items:center ⇒ 这些文字行的宽度是 fit-content，实测 .cname 的 computed width 只有 81.16px（正好等于它自己文字的宽）。而导出引擎 inlineStyles() 会把 computed width 这个具体像素内联进 SVG ⇒ SVG 里 .cname 被钉死成 81px。 SVG 的字体度量与真实 DOM 有极小差异（哪怕 1px），「六九樂章」在 81px 里就放不下 ⇒ 被迫换行成两行 ⇒ .smain 内容超出 aspect-ratio:1/1 的定高 ⇒ flex 项目被压缩 ⇒ 两行叠在一起。
预览不叠，是因为真实 DOM 里宽度跟着内容走，永远不会"被迫换行"。
修法：文字行显式 width:100% + text-align:center（视觉与改前完全一致，文字仍居中）， 并加 flex:0 0 auto 关掉收缩 —— 宁可顶开也绝不叠字。
实测：手机/桌面 / 正常与阻断 fetch 三种场景，叠字 0 组、文字溢出卡外 0 个。
④ 用户自建的组合要点两下才能加载已修 根因：applyCombo 把「回源核准歌手姓名」放在 await 里 等完才赋值 picked ⇒ 点下去到界面有反应之间有 2N 次网络请求，这段时间界面 一点变化都没有（只有按钮文字变成"装填中…"），用户以为没点上就再点一下 —— 第二下时请求已完成/已缓存，看着就像"第二下才灵"。
修法：乐观更新 —— 先用组合里已存的快照（artistId + name）立刻装进 picked （摘要、已选标签、专辑池加载全部立刻开始），回源核准改成不阻塞界面的后台校正， 姓名真的与快照不符时才更新（第三十八批"名字与专辑对不上"的修复照样成立）。
实测：建一个真·自建组合 → 点一下 → 404ms 内摘要就变成 「已选 8 张 · 来自 2 位歌手 · 赛程…」；2.6s 后完整装填。
