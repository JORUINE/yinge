已修 #5 分享图导出：手机端存不下来的根因找到了

你的原话："我们导出分享图电脑端是靠截图实现 可以下载 但是手机端经过我实测 截图有问题 无法下载 导出来的图也是错误有问题的 这一条也是需要重点优化"

根因
旧实现两个手机端必失败的原因（都已实测确认）： ① <a download="xxx.png"> + click() —— iOS Safari 与微信内置浏览器都不支持 download 属性，点了只会尝试打开图片，存不下来； ② canvas.toDataURL() 把整张图编成 base64 塞进 href —— 1080×1439 的 PNG 动辄 2~5MB，手机上这个 URL 直接被判死
怎么修的
① 渲染换成项目里已验证的 exportNodeToPng（克隆节点 + 内联 computed style + SVG foreignObject 交给浏览器真渲染引擎）—— 间距/圆角/字体/渐变所见即所得，不再有 html2canvas 自己算布局丢间距的老毛病； ② 下载改成移动端友好的三级降级：能走 navigator.share({files}) 就调系统分享面板（存相册最顺）→ 否则 toBlob + createObjectURL（比 dataURL 省一个数量级内存）→ 桌面端仍保留 <a download> → iOS 以上都不行就新窗口打开图片并提示"长按保存"
顺带
人格分享保存不了（#6 后半句）是同一个根因，已一起修
复验
桌面端 A/B 0 差异（分享页布局没动）、三档断点全绿、布局体检问题数没增加
