一、手机复制链接：为什么只弹了一条灰条

1
非安全上下文没有剪贴板 API
只在 https:// 或 localhost 下 navigator.clipboard 才存在。 手机通过 http://192.168.1.65:5173 打开时它是 undefined （已实测：isSecureContext=false、navigator.clipboard=false）。
2
旧代码把它当成"复制失败"就结束了
try { await navigator.clipboard.writeText(url) } catch { ElMessage.info(url) } —— catch 里只是把链接**显示**出来（就是用户截图里那条灰条），从来没有写进剪贴板。 所以"好友一起玩"的分享链接等于废了。
3
现在的三级兜底
① 非安全上下文：**同步** document.execCommand('copy')（必须在用户手势里，不能先 await）； ② 安全上下文：Clipboard API；③ 都失败：弹出只读输入框并**自动全选**，提示长按拷贝。 全程失败才降级，不会再出现"看起来复制了其实没有"。
验证（真机条件：局域网 http，非安全上下文）结果
window.isSecureContext / navigator.clipboardfalse / undefined（与手机一致）
点「复制链接分享」后的提示「链接已复制」（不再是灰条）
剪贴板实际内容（从安全页读取）= 本场链接，逐字符一致
强制两种复制都失败弹出兜底弹窗：只读、已全选、文案说明「长按点拷贝」

二、人格维度：13/10、18/10 是怎么来的

根因不是"算错了"，是"两代数据被当成同一种量纲"。
· 2026-09 之前的记录：scores = { melody: 9, rhythm: 13, arrangement: 18, calm: 10 } —— 原始分，本来就没有"满分 10"的概念；
· 之后改成 6 维计分：scores = { _display: {…0~1…}, _norm, _raw }；
· 前端只有一套换算 n <= 1 ? n*10 : n：旧数据 13 → 直接印成「13 / 10」； 而人格卡组件内部 clamp(0,10) → 同一个 13 显示成 10/10 ⇒ 左右对不上。

为什么旧记录不能"重算"

试过按旧答卷重算（题目还在库里），但实测发现旧题目的选项分值已被重写： 同一条记录旧 raw 是 melody 9 / rhythm 13 / arrangement 11， 按现在的选项分重算得到 melody 24 / rhythm 13 / texture 1 —— 那已经是"另一份答卷"。 与其编一个看起来合理的数字，不如如实说明。
