音格 · 视觉还原方案与排期

以 docs/design/音格-UI设计稿.html（19 页高保真原型） 为唯一 1:1 还原基准，音乐海洋（玻璃拟态）方向，含浅色 + 深色双主题。本方案先锁定目标、对齐设计系统、列出 19 页映射与排期，再请你确认后动工。

结论先行

0一句话结论与边界

做什么：把仓库里已有的 20 个 Vue 视图，按原型逐页重做成 1:1 还原（布局、配色、字号、间距、组件、动效、深色模式全部对齐），并补齐原型有、但路由/视图还缺的页面（对阵表、夺冠之路分享图、我的对决、收藏）。

1:1 还原的是「页面内容」：即原型每个 .screen 内的真实产品 UI（顶部导航、英雄区、卡片、列表、对战舞台、榜单等）。原型外层的 .frame 设备框、.frame-bar 地址栏、.side 原型目录侧栏属于「原型自带的展示外壳」，不是产品 UI，不还原。

不做：不引入原型没有的设计语言；不照搬「音乐世界杯」的玩法口径（你的原话：我们不是音乐世界杯，是专辑比拼，是音格）。对决规则以原型 p5 的说明（非 2 的幂怎么分组、晋级逻辑）为准，由音格自己的产品逻辑论证。

提交方式：代码改动仍由你 用 GitHub Desktop 推送（我不会给你命令行 push 步骤）。

验收

61:1 还原验收标准（交付前逐条核对）

  • 令牌层：页面所有颜色/字号/间距/圆角/阴影走 CSS 变量，且与设计稿 :root 逐项一致；不出现散写十六进制（除逐专辑主色 --ac 由脚本注入）。
  • 布局层：与截图同结构、同栅格、同留白；桌面 1180 容器，移动端单列不横向溢出。
  • 组件层：复用 §2 提取的组件类，视觉与截图一致（如 vstage 光晕随专辑主色变化、gstrip 战绩条、nowbar 播放条三键布局）。
  • 双主题：浅色 + 深色都还原；深色下玻璃提亮、败方压暗、硬色替换等 20+ 微调到位。
  • 动效：入场 rise、hover 位移/阴影、光晕「你点才亮」均 150–300ms，且 prefers-reduced-motion 关闭。
  • 无障碍：无 emoji 图标（一律 SVG）、可点击元素 cursor:pointer、焦点环可见、文字对比 ≥ 4.5:1。
  • 数字一致性：场次、页数、字段、进度数与后端公式一致；同数字多页口径相同；互斥状态不并存（已结束 vs 进行中）。
交付节奏承诺：每个阶段结束都跑一次《自检清单》并把结果贴给你看（不是只在脑子里过一遍）；重大改动先出方案等你批准；所有改动走备份 + 改动记录；代码由你用 GitHub Desktop 推送。
