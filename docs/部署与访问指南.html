部署与访问指南

写给不写代码的你：怎么在自己电脑看、怎么放到网上给别人看、几个待办到底是啥。

1一句话总览

现在：音格只运行在你自己的电脑上（localhost），只有你这台电脑能打开，别人打不开。

部署后：把网站放到云服务器上，任何人拿到链接都能打开 —— 这正是毕业规范要求的"线上演示地址"。

你之前说"我跑了下页面大体没问题"，说明你其实已经会在本机启动了。下面把命令和端口说准，免得下次忘了。

2现在怎么在本地访问（本机自己看）

需要三样东西同时开着：数据库 → 后台(后端) → 前台(网页)。

角色是什么启动命令端口
数据库 MongoDB存所有数据的地方mongod27017
后台 / 后端处理登录、投票、排行榜等接口的 Node 程序cd backend && npm start3000
前台 / 网页你看到的 Vue 网站cd frontend && npm run dev5173

完整步骤（按顺序开三个窗口）：

# 窗口1：开数据库
mongod

# 窗口2：开后盾（接口服务）
cd E:\桌面\毕业设计\yinge\backend
npm start

# 窗口3：开前台（网页）
cd E:\桌面\毕业设计\yinge\frontend
npm run dev

三步都开着后，浏览器打开 👉 http://localhost:5173 就是音格网站。

两个坑（之前记错，现已更正）：
① 前端命令是 npm run dev，不是 npm run serve；端口是 5173，不是 8080。
② 如果你的电脑默认 Node 是 18，启动会报 error:0308010C 的错。解决：用 Node 20 以上（你机器上托管了 Node 22）。用 20+ 就不用管那个报错。

3"后台""前台"到底啥意思

打个比方 —— 音格像一家餐厅：

前台（网页 / frontend）

顾客坐的用餐区 + 菜单。就是你在浏览器里看到的页面、点的按钮。它自己不会算账，只负责"展示"和"收集你的操作"。

后台（后端 / backend）

后厨 + 服务员。网页把"我要投票""查排行榜"这种请求发给后台，后台去数据库查数据、算结果，再把数据回传给网页显示。端口 3000 就是后厨的门。

所以"后台运行"= 那个 3000 端口的 Node 程序正在跑。它一关，网页上的投票、排行榜就全失效了。两者必须同时开着。

4怎么部署（拿到公开网址，给别人看）

为什么必须部署：localhost 只有你电脑认，发链接给别人是打不开的。毕业要交"线上演示地址"，就得部署。

三块分别放哪（都用免费档就够）：

部分放哪个云平台作用
网页(前台)Vercel（免费）托管 Vue 网站，给一个 https 网址
接口(后台)Render（免费档）跑 Node 后端，给后端一个网址
数据库MongoDB Atlas（免费 M0）云端数据库，代替你本机的 mongod

大致步骤（需要你动手的地方我标了 ⚡）：

# 1. ⚡你注册三个账号：Vercel / Render / MongoDB Atlas（都用邮箱，免费）
# 2. 把 GitHub 仓库连到 Vercel 和 Render（授权一次即可）
# 3. ⚡在 Render 里填几个环境变量（我给你列好清单）
# 4. 在 Atlas 建一个库，拿到连接串，填进 Render
# 5. 点 Deploy —— 几分钟后拿到两个网址
# 6. 把后端网址填进前端的环境变量，重新部署前端

6六个人格怎么补（图鉴页"常听专辑"现在是空的）

音格有 6 种音乐人格，已经建好在数据库里：

类型码名称特点
EN电音狂热者高能量、爱社交
NT深夜循环者怀旧、夜里听

现在缺什么：这 6 种类型没有绑定"推荐专辑"，所以前台"人格图鉴 / 类型详情"里的"常听专辑"是空的。

好消息：后端的字段、接口、取数逻辑全都已经写好（字段叫 recommendAlbumIds，后台接口也支持传它）。唯一缺口是：后台管理页面目前没有"推荐专辑"这个输入框。

两种补法（你选一种，我来动手）：

A. 我给后台加输入框

在"人格类型管理"页加一个"推荐专辑ID"输入框，你以后自己在后台填专辑ID就行。简单、你能掌控。

B. 我写脚本自动绑

我直接写个脚本，给每种类型自动绑 3 张专辑。前提：专辑得先在数据库里——先用后台"曲库"刷一批歌手（比如周杰伦、陶喆等）把专辑灌进库。

推荐先做 B 的前置：用后台"曲库"刷 10~20 个歌手，库里有专辑了，A 和 B 才填得进去。
