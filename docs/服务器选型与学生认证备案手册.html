三个问题，先给结论：
学生认证怎么弄 实名 → university.aliyun.com → 学生认证 → 学信网认证（支付宝扫码，1~3 分钟自动过） → 领 300 元券。 过不了就转人工（学信网截图 + 手持学生证）。每年只能领一次券。
买哪台 2 核 4G（ECS 通用型 或 轻量应用服务器），不要 1 核 2G，也不要突发性能型 t6/t5。
2 核 2G 够不够 能跑，但不该买。不是数据装不下（我们整库才 20.5MB），是内存被三方分完： MongoDB 默认要吃掉一半内存做缓存，剩下的要养 Node + Nginx + 系统， 真正出事的是在服务器上跑一次构建——2G 基本必 OOM。见第二节的账。

为什么磁盘上看到 408MB？那是 mongod 的数据目录总量，包含 journal 预分配、诊断日志、索引重建的临时文件。 真实数据只有 20.5MB（压缩后存储 11MB、索引 4.1MB）。 ⇒ 我们永远不是因为"数据大"需要升配，40G 系统盘绰绰有余。

二、2 核 2G 到底够不够：把内存账算给你看

2G 内存不是"全给你用"，是四家分：

Linux 系统本身
250 ~ 350 MB
MongoDB
≈ 500 MB 缓存 + 100 MB 自身 （WiredTiger 默认缓存 = (内存−1G)×50%）
Node 后端
120 ~ 200 MB
Nginx + 监控
30 ~ 50 MB
合计
≈ 1.1 GB
2G 机器上，日常运行后剩余：
约 900MB 余量 —— 平时够，但没有冗余
真正会翻车的是这三件事，不是"人多"：
  1. 在服务器上跑 npm install / vite build：Node 构建进程峰值能吃到 800MB~1.5GB， 2G 机器直接 OOM，SSH 都连不上。对策：本地构建好，只上传 dist（3.2MB）。
  2. MongoDB 备份 / 建索引：会临时拉高内存与 IO，2G 上容易把 Node 挤到 swap，页面卡死几秒。
  3. 封面图代理并发：我们的图片走同源代理，几十个人同时刷封面时，CPU 会被打满（这是 CPU 问题，不是内存）。

结论与推荐

方案评价为什么
1 核 2G（学生免费机常见档） 不推荐 单核 + 2G，Mongo 与 Node 抢 CPU；只能当练习机。且免费试用实例不支持备案（官方明确）。
2 核 2G 能跑，但不该买 日常够用，但没有冗余：一次备份或一次误操作上服务器构建就 OOM。你说要"面对真实用户 + 冗余"，这一档不满足。
2 核 4G ✅ 推荐 Mongo 缓存能给到 1.5G、Node 与系统各留余量；能直接在机上构建、能扛几百日活； 多出来的钱通常一年也就一百多。这就是"冗余"最划算的一档。
4 核 8G 没必要（现在） 我们没有任何重计算在后端（图片导出全在浏览器里做）。钱应该先花在带宽/CDN 和备份上。
⚠️ 别买「突发性能型」（t6 / t5 / 经济型 e 的突发款）： 这类机器靠 CPU 积分，积分用完会掉到 10%~20% 基线性能。 你看着是 2 核，实际高峰期比 1 核还慢，而且"卡"得毫无规律、很难排查。 买通用型（g 系列）或轻量应用服务器。

真正的"冗余"应该这么做（不靠堆配置）

  1. 静态资源上 OSS + CDN：dist 只有 3.2MB，放 OSS 后服务器只跑 API，省带宽也抗打。
  2. 开 2G swap：给 OOM 一个缓冲垫（fallocate -l 2G /swapfile），突发时不会直接弄死进程。
  3. MongoDB 每天自动备份到 OSS，保留 7 天 —— 数据只有 20MB，备份几乎零成本。
  4. 应用保持无状态：会话走 JWT、图片走外链，机器挂了换一台重跑部署脚本就能起（这也是我们现在的架构）。
  5. 图片别自己扛：封面优先用外链 CDN，同源代理只做兜底并加缓存头。

三、阿里云学生认证：一步一步

前置条件：① 阿里云账号已完成个人实名认证（身份证 + 人脸）； ② 你的学校在阿里云合作范围内（大部分公办/民办本科都在，但不是全部）； ③ 学信网能查到你的学籍。
  1. 进高校计划页
    电脑浏览器打开 university.aliyun.com， 登录你的阿里云账号 → 点「学生认证」。
    手机也可以：阿里云 App → 底部「发现」→「普惠权益」→「高校」→ 完成学生认证后领取。
  2. 选「学信网认证」
    系统会让你确认"账号实名信息 = 支付宝实名信息"，同意后用支付宝扫码授权， 阿里云会向学信网核验学籍。1~3 分钟自动出结果。
    算成功：页面显示"已完成学生身份验证"，券包里出现 300 元券。
  3. 如果自动认证失败 → 转人工
    准备两样东西（官方要求，缺一样会被打回）：
    ① 学信网截图：必须能看到学信网标志、学生照片、姓名、身份证号、学籍状态； 如果学信网没有照片，额外要提供手持身份证照片。
    ② 手持学生证照片：要包含本人上半身 + 学生证信息页（照片、钢印、学号、姓名）。 学生证还没发？可用含学号/姓名/照片的学生卡或学校官方证件替代。
    ⚠️ 录取通知书封面不能单独作为有效凭证。
    算成功：1~3 个工作日后收到审核结果。
  4. 领券
    认证通过后在「学生用券中心」领 300 元无门槛抵扣金。 一个身份证一年只能领一次，领了就算当年用完；券有有效期，过期作废（以券面显示为准）。
  5. 用它下单
    在「学生用券中心」里挑 2 核 4G 的轻量应用服务器 / ECS，下单时勾选使用代金券。 务必看清计费方式是"包年包月"且时长 ≥ 3 个月（备案硬要求，见第五节）。
三个容易踩的点： ① 有人说"0 元免费机"——那种免费试用实例不能用于备案（阿里云官方明确），想上线必须买正式的包年包月； ② 学生认证毕业后权益失效，已买的机器按原价续费； ③ 若提示"查不到学籍"，先确认学校是否在合作名单、姓名/身份证/入学年份是否与学信网完全一致。

为什么是两台？
  • 香港机（2 核 2G 也行）：免备案，买完当天就能把网站挂上去给老师看。 它只承担"演示 + 开发测试"，不需要冗余。

五、域名备案：从买到能用，全流程

先满足三个硬条件（缺一个都提交不了）

条件具体要求
服务器阿里云中国内地节点（香港/海外不需要备案，也不能在阿里云备案）； 包年包月，购买时长 > 3 个月（含续费累计）；必须购买公网带宽。
免费试用 ECS 不满足；按量付费要先转包年包月。
域名已完成域名实名认证（用同一个身份证）。非阿里云注册的域名也能在阿里云备案（备案跟服务器走，不跟域名注册商走）。
主体个人备案：身份证、本人手机号、能人脸核验。姓名必须和实名、域名实名、备案主体完全一致，错一个字都要重来。
一个账号同时只能有一个"备案中"的订单。所以：一次把要备案的域名填全，别想着"先备一个试试"。
  1. 买好国内机 + 域名（域名先别解析）
    国内机选包年（≥3 个月是底线，建议直接一年）；域名买完立刻做域名实名，通常几小时到 1 天。
    ⚠️ 备案期间域名不要解析到大陆服务器，否则会被监测阻断，反而影响审核。
  2. 进备案系统，选「首次备案」
    beian.aliyun.com → 用买了国内服务器的那同一个阿里云账号登录 → 开始备案。 如果服务器和备案账号是同一个账号，系统会自动生成"备案服务码"，不用你手动申请。
  3. 填主体信息（个人）
    姓名、身份证号、手机号、常用邮箱、通信地址（要精确到门牌号）。地址写得含糊是最常见驳回原因之一。
  4. 填网站信息
    网站名称、域名、网站服务内容、网站负责人。
    个人主体的写法建议：网站名称里带上"个人"字样（如"音格 · 个人作品展示"）， 服务内容选「其他」或「博客 / 个人空间」类，不要选"论坛""社区""电商"。
    个人备案不得从事经营性活动：不能卖东西、不能放收费广告。
  5. 上传材料 + 人脸核验
    身份证正反面照片（四角完整、无反光）、手写承诺书（如需）、 用阿里云 App 扫脸完成网站负责人核验。按系统提示逐步上传即可，每一步都有示例图。
  6. 阿里云初审（1~2 个工作日）
    会打电话给你核验（注意接听陌生号码）。材料有问题会告诉你改哪里；没问题直接提交管局。
  7. 工信部短信核验（收到后 24 小时内必须完成）
    手机会收到工信部短信，里面有 6 位验证码。去工信部备案系统输入 验证码 + 手机号 + 身份证后 6 位完成核验。超时未核验，订单会被退回重来。
  8. 管局审核（最长 20 个工作日）
    各省速度不同，快的几天、慢的两三周。期间什么都不用做，可在阿里云后台查进度。
  9. 下号 → 解析域名 → 挂备案号
    拿到备案号（形如 蜀ICP备2026XXXXXX号）后，才把域名解析到国内机； 备案号必须挂在网站页脚（法规要求），把号发我，我加到页脚。
  10. 公安联网备案（30 日内，最容易被忘）
    ICP 备案成功后，须在网站开通之日起 30 日内，到 全国互联网安全管理服务平台 办理公安联网备案，拿到公安备案号，同样挂在页脚。
