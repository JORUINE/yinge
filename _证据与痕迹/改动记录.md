  - 新增 `stop-dev.bat`：停 MongoDB。
  - **修掉一个真错误**：原 `桌面\毕业设计\start-dev.bat` 写的是 `npm run serve`，而前端脚本名是 `dev` → 以前这样启动前端必然失败；现已改为委托给仓库内的新启动器。
- **② 投票页 `BattlePlayView.vue` 按 v2 重做（P1③）**
  - 小组 / 复活阶段：**一次多选 K 张**（选满 advanceCount 才能提交，`/next-step` + `/groups/:id/vote`），含「已选 X / K」计数、清空重选。
  - 淘汰赛阶段：1v1 舞台（vstage + 专辑主色光晕 + 试听 30 秒 + 播放条 + 投给《…》按钮）。
  - 进度显示「已投 X / Y 步」；专辑主色由 albumId 稳定映射（近似还原设计稿「背景跟着专辑变」）。

  - `api/index.js` 新增 `nextStep` / `groupVote`。
- **③ ⚠️ 修复一个会挡住整个小组赛的真 bug：votes 集合残留旧唯一索引**
  - **现象**：新建 v2 对决后，第一组小组投票就报「记录已存在，请勿重复操作」（E11000）。
  - **根因**：Vote 早期版本唯一索引是**非 partial** 的 `(matchId, userId)`；v2 改成 partial 后，MongoDB **不会自动删除旧索引**。小组投票一次性插入多条 `matchId = null` 的记录 → 撞上旧的非 partial 唯一索引。
  - **修复**：新增 `scripts/migrate-drop-stale-indexes.mjs`（幂等）删除遗留索引 `votes.matchId_1_userId_1`，保留新的 partial 索引；启动器已自动调用。
- **验证（真实后端 E2E，非推测）**
  - 建 v2 对决：`stepTotal=5 · 小组 2 组 · 淘汰赛 4 强 · 版本 2`（与 `planTournament(8)` 一致）
  - 第 1 步 `phase=group` 第 1 组 `advance=2` 候选 4 张 `progress 0/5`
  - 小组投票 **ok** → 第 2 步推进到第 2 组 `progress 1/5`
  - 非法投票（只选 1 张）**被正确拒绝**：「本分组需选择 2 张专辑晋级」
