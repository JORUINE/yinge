## 2026-09-17 · 新赛制 v2 后端接线（提交 179551c）

- **改动名**：tournamentV2-backend-wiring
- **范围**：后端「专辑对决」新赛制 `tournamentVersion = 2` 从公式层接进真实数据流（创建 → 小组 4 选 2 → 遗珠复活 → 1v1 淘汰 → 冠军）
- **改前**：第 1 步只完成公式层（`bracket.js` 的 `planTournament` 等），未接真实数据，新赛制无法运行
- **改后**：新赛制可端到端运行；旧赛制（`tournamentVersion` 默认 1）路径未改动，灰度共存
- **涉及文件与要点**
  - 新增 `backend/src/models/BattleGroup.js`：小组 / 复活多选环节集合（battleId / roundName / groupNo / albumIds / advanceCount / pickedAlbumIds / pickedAt）
  - `models/index.js`：导出 `BattleGroup`
  - `models/Vote.js`：`matchId` 改可选 + 新增 `groupId` + 两个 `partialFilterExpression` 唯一索引（matchId 投票 / groupId+userId+albumId 多选投票）
  - `models/Battle.js`：新增 `tournamentVersion / poolTarget / knockoutSize / revivalNeed / stepTotal`
  - `models/BattleMatch.js`：`ROUND_NAMES` 扩展含 `r32 / r16 / qf`
  - `modules/battles/bracket.js`：新增 `roundNameFor / buildGroupDefs / buildGroupDefsCrossArtist / buildKnockoutRound` + KO 相关常量（旧函数一律未动）
  - `battle.service.js`：新增 `createBattleV2 / castGroupVote / getNextStep / progressGroupRevivalV2 / startKnockoutV2 / progressKnockoutV2`；`createBattle` 与 `progressBattle` 增加 v2 分发；`getResult` 增加 `groupsSummary`；分组投票限流改用 `config.vote.minIntervalMs`
  - `battles.controller.js`：`serializeBattle` 增加新赛制字段；新增 `nextStep / groupVote` 处理器
  - `battles.routes.js`：新增 `GET /:id/next-step`、`POST /:id/groups/:groupId/vote`；`createSchema` 增加 `tournamentVersion`（1|2）
  - 新增 `backend/scripts/verify-v2.mjs`：真实连库（独立测试库 `yinge_test`，跑完即删）端到端验证
- **原因**：把已定稿的赛制公式接到真实数据，使新赛制可跑起来给人用；同时修正"已投 6/16 场"这类步数不自洽的问题（总步数由 `planTournament` 唯一推出，已投步数 = 总步数）
- **验证**
  - `verify-v2.mjs`：**59 / 59 通过**（多歌手 3×8=24 张 → 22 步；单歌手 16 张 → 11 步；冠军均决出；已投步数 = 总步数）
  - `verify-scale.mjs`：**152 / 152 无回归**（纯公式层，未改动）
  - v1 路径（`tournamentVersion` 默认 1）代码未改动，保持原有回归覆盖
- **回退**：`git revert 179551c`（或 `git checkout 179551c^ -- backend/src/modules/battles/ backend/src/models/`）

### 自检结论（交付前必跑，已跑）
- 数字一致性：步数 = 组数 +（有复活 ? 1 : 0）+ 淘汰赛场次，由 `planTournament` 一次性推出，前端"已投 X / 总步数 Y"两处同源 → 不会出现 6/16 这类矛盾
- 跨文档口径：本次只动后端；前端 / 需求 / 设计 / 接口文档的 v2 口径对齐留到第 6 步（后期功能清单），届时统一回填
- 互斥状态：已结束对决不可再投票（`status !== 'playing'` 拦截）；分组已投不可重复投（`isPicked()` + 唯一索引兜底）

## 2026-09-17 · 视觉还原 P1①：设计系统对齐 + 创建页 1:1 + v2 规模选择器

- **改动名**：visual-restore-p1-design-system-and-create
- **范围**：前端。第 0 步（设计系统对齐）+ 对决主线第 ① 屏（创建页）
- **改前**：`tokens.css` 只有轻量骨架（无玻璃 / Aurora / 深色 / 人格色）；`AppShell` 顶栏是 Element Plus 风格；`BattleCreateView` 是 Element Plus 表单堆叠，**没有 v2 规模选择器**（用户点名要的"自选每位歌手几张"）
- **改后**：

  - `BattleCreateView.vue`：重建为设计稿 p4 结构（六模式 `.modes` / 对位说明 `.alignbox` / 歌手 `.chips` / 快速搜索 `.presets` / 准入过滤 `.tipbar` / 专辑池 `.pool` / 开始条 `.startbar`）；**新增 v2 参赛规模选择器**（单歌手 8/12/16/24/32，多歌手每位 4/6/8/10），开始条实时显示"已选 N 张 · M 位歌手 · 赛程：…· 共 X 步"
